SMPSFormat — Module
SMPSFormat

Read and write stochastic linear programs in the SMPS format (Birge et al., 1987; Gassmann's description of the format; Gassmann and Kristjánsson, 2007): a core file, the deterministic problem in MPS format; a time file, which splits it into stages; a stoch file, the law of its random data.

  • read_smps reads the three files of a two-stage instance into an SMPSProblem: the data of each stage as matrices and vectors, the random elements, and their law, an SMPSLaw. An instance in more periods is read into an SMPSTree, its scenario tree, or, when its random data are given period by period (INDEP, BLOCKS), into an SMPSStagewise, from which scenario_tree builds the tree and sample_tree samples one; scenario_data gives the data of a scenario, bundles the scenarios that share a node.
  • The law can be enumerated, enumerate_scenarios, when it is discrete, and sampled, rand(rng, law, n); second_stage gives the data of the second stage in a scenario.
  • write_smps writes a problem back: a two-stage problem with its law or with given scenarios, a tree, a law by period. scenario_tree and sample_tree also turn a two-stage problem into a tree in two periods, so that a code written for trees treats both.
  • With JuMP loaded, extensive_form builds the deterministic equivalent: for given scenarios of a two-stage instance, or on the tree of a multistage one.

The package has a behavior of its own, meant to read the files of the literature as they are written (SPLIB, POSTS, Felt's test set, SAPHIR): comment lines anywhere, free format, problem names that differ between the files (a warning), probabilities rounded to the digits written (normalized), scenario trees in two stages or more, time and stoch files whose first section is NAME.

Reading and writing

SMPSFormat.read_smps — Function
read_smps(core, time, stoch; sense = nothing, probability_sums = :rounding, format = :free)
read_smps(prefix; sense = nothing, probability_sums = :rounding, format = :free)

Read an instance in the SMPS format: an instance in two periods into an SMPSProblem; one in more periods into an SMPSTree, its scenario tree, when its stoch file gives the tree (SCENARIOS), or into an SMPSStagewise, a law by period, when it gives INDEP and BLOCKS sections. read_smps(prefix) looks for prefix followed by .cor or .core, .tim or .time, and .sto or .stoch, each possibly followed by .gz: a file whose name ends in .gz is read through gzip. An error in a file names it and the line read.

format: :free, the default, reads the fields separated by blanks (free MPS, which also reads most fixed files); :fixed reads them in the columns of fixed MPS, so that names may contain blanks (a word belongs to the field it starts in, or to the next one if it starts between two; what starts after column 61 is ignored). It applies to the three files, and only suits files in fixed format: a compact layout is read in free format.

The core file is in free MPS format: NAME, OBJSENSE, OBJNAME, ROWS, COLUMNS (with integer markers), RHS, RANGES and BOUNDS (UP, LO, FX, FR, MI, PL, BV, LI, UI). Integer variables without bounds lie in [0, ∞). A negative upper bound alone frees the lower one, as in MPS. As MPS and CoinMpsIO read them: the objective is the first row of type N, or the one OBJNAME names; of several RHS, RANGES or BOUNDS vectors, only the first is used, with a warning; a line with a hash in the first column is a comment.

The time file gives the periods, implicitly (the first column and row of each, the core file being in temporal order) or explicitly (PERIODS EXPLICIT, then the period of each column and row), in any number.

The stoch file of a two-period instance gives the law of the random elements, which may be right-hand sides, matrix coefficients and costs of the second stage:

  • INDEP sections, DISCRETE or continuous: UNIFORM (a, b), NORMAL (mean, variance), GAMMA (scale, shape), BETA (the two parameters of Beta(n, m), density ∝ x^(n−1)(1−x)^(m−1)), LOGNORM (mean and variance of the logarithm). A continuous law can be sampled only.
  • BLOCKS DISCRETE: an element a realization does not list takes its value in the block's first realization, as the format says.
  • Random bounds of second-stage variables, in BLOCKS and SCENARIOS sections, written as the core file's BOUNDS section writes them (UP BND X1 5.0): UP sets the upper bound, LO the lower one, FX both; the other types are refused.
  • SCENARIOS DISCRETE (or SCEN) in two stages: each scenario branches from ROOT, or from another scenario at the second period, and inherits the values it does not list from its parent (the core file for ROOT).
  • The modifiers REPLACE (the default), ADD and MULTIPLY of INDEP and BLOCKS sections: the value given replaces the core value, is added to it, or multiplies it.

The stoch file of an instance in more periods, with INDEP and BLOCKS sections, gives the law of each period, as in two periods (distributions, modifiers, random bounds), each element or block in the period its line gives: the period it is revealed in, the second at least, and at most the period of the data it sets (a demand of the third period may be known in the second). An INDEP line without a period is revealed in the period of its data. The laws of the periods are independent of each other.

The stoch file of an instance in more periods, with a SCENARIOS section, gives its scenario tree, in a SCENARIOS DISCRETE (or SCEN) section, REPLACE: each scenario branches from ROOT, or from a scenario given before it, in the period its SC line gives. Before that period it shares the nodes of its parent; from that period on it has nodes of its own, and inherits the values it does not list from its parent (the core file for ROOT). It may change only data of its branching period or later: right-hand sides, matrix coefficients, costs and bounds (UP, LO, FX, written as in the core file's BOUNDS section). The tree has one node in the first period: a scenario branching from ROOT in the first period, as in the SGPF files of POSTS, must be the only child of ROOT, and then sets the data of the first period. Without any scenario, the tree is a single one, the core problem.

Not supported, and refused: NODES, DISTRIB, MVNORMAL, LINTRAN and user-defined distributions, SCENARIOS with INDEP or BLOCKS in more than two periods, chance constraints (CHANCE, ICC), SIMPLE recourse, random ranges, random bounds in INDEP sections or of types other than UP, LO and FX, random first-stage data in two periods, network core files.

The names on the first lines of the three files should be the same; when they are not, as in several files of SPLIB, a warning. A time or stoch file whose first section is NAME, instead of TIME or STOCH, as some of SMI's, is read as well.

sense: :min or :max, overriding the file's OBJSENSE (for a maximization whose files do not say so, as SAPHIR's); by default, the file's, or :min. A maximization is stored as the minimization of the opposite objective (see SMPSProblem).

probability_sums: probabilities written with a few digits, as 1/6 as 0.16667, sum up to one only up to their rounding. What to do with those of a block (an INDEP element, a BLOCKS block, or the scenarios) that do not sum up to one:

  • :rounding, the default: normalized when the gap is within the rounding of the digits written (the number of outcomes times half a unit of their last digit), with a warning if it is not negligible; refused beyond, the file then being taken as wrong.
  • :normalize: normalized, with a warning if the gap is not negligible.
  • :as_written: kept as written, with a warning; the probabilities of the scenarios then sum up to the product of their totals, and the expected recourse is weighted by them. Zverovich's thesis (2011) solved SPLIB's instances so, and its published values are reproduced only this way. In a tree, each node then has the total probability of its scenarios, the root the sum of them all.

SMPSFormat.write_smps — Function
write_smps(prefix, smps::SMPSProblem; scenarios = nothing)
write_smps(prefix, tree::SMPSTree)
write_smps(prefix, s::SMPSStagewise)

Write an instance in the SMPS format to prefix.cor, prefix.tim and prefix.sto, and return their paths. read_smps reads them back into the same problem.

  • The core file is in free MPS format, the columns and rows in the order of their periods, so that the time file gives each period by its first column and row; when a period has none, the time file lists the period of each (PERIODS EXPLICIT). A maximization is written as such, with an OBJSENSE MAX section.
  • The stoch file of a two-stage problem or of a law by period gives the law: its continuous elements and its discrete blocks of one element in INDEP sections, its other blocks in BLOCKS DISCRETE sections, each realization listing every element of its block, each line in the period it is revealed in. For a two-stage problem, scenarios = (ξ = ..., p = ...) lists those scenarios instead (SCENARIOS DISCRETE), each giving the values that differ from the core file: an instance whose scenarios were sampled, or generated.
  • The stoch file of a tree lists its scenarios (SCENARIOS DISCRETE): each branches from the first scenario that shares its node in the period before its first node of its own, and gives the values that differ from those it inherits. The data of the root are those of the core file.

The numbers are written in full, so that they are read back exactly.

Two-stage problems

SMPSFormat.SMPSProblem — Type
SMPSProblem

A two-stage problem read by read_smps:

min  c'x + E[ q(ξ)'y ] + constant
s.t. A x  ~ b                 (senses1, ranges1)
     T(ξ) x + W(ξ) y ~ h(ξ)   (senses2, ranges2)
     lb1 ≤ x ≤ ub1,  lb ≤ y ≤ ub,  some of them integer
  • Rows: each has a sense, 'L', 'G' or 'E', a right-hand side, and a range, NaN when it has none (the RANGES section of MPS); row_bounds gives the interval it imposes.
  • Random elements: elements lists them as (kind, i, j). (:h, i, 0) is the right-hand side of the second-stage row i; (:T, i, j) the coefficient of the first-stage variable j in that row; (:W, i, j) that of the second-stage variable j; (:q, j, 0) the cost of the second-stage variable j; (:lb, j, 0) and (:ub, j, 0) its lower and upper bounds. names gives, for each, the column and row names of the files, or, for a bound, its type (LO or UP) and the column. law is their law; second_stage gives the data of the second stage for one ξ.
  • Sense: sense is :min or :max. A maximization is stored as the minimization of the opposite objective: every cost, random ones included, and the constant, are negated.
  • Names: columns1, columns2, rows1 and rows2 are those of the files; objective is the name of the objective row.

SMPSFormat.SMPSLaw — Type
SMPSLaw

The law of ξ, the vector of the values of the random elements of an SMPSProblem, in the order of its elements:

  • Discrete blocks, independent of each other, each taking one of finitely many outcomes, which set the values of some elements. An INDEP DISCRETE element is a block of its own; a BLOCKS block sets several elements at once; a two-stage SCENARIOS section is a single block whose outcomes are the scenarios.
  • Continuous elements, INDEP with a continuous distribution, each independent of the rest. Each is (element, distribution, modifier, sign): a draw v gives the value sign × modified(sign × base, v), sign being −1 for a cost of a maximization (stored negated).

base holds the values of the core file; an element no block or distribution sets keeps it. The outcomes hold the values themselves: ADD and MULTIPLY are applied when the file is read. A continuous element keeps its modifier, applied to each draw.

rand(rng, law) draws one ξ, rand(rng, law, n) draws n independent ones. A discrete law can be enumerated, enumerate_scenarios.

SMPSFormat.enumerate_scenarios — Function
enumerate_scenarios(law::SMPSLaw; limit = 100_000)

Every point of the support of a discrete law and its probability, as the named tuple (ξ = ..., p = ...); the last block varies fastest. An error if there are more than limit of them (sample the law instead, rand(rng, law, n)), or if the law has continuous elements.

SMPSFormat.row_bounds — Function
row_bounds(sense, rhs, range)

The interval (lower, upper) a row of sense sense ('L', 'G' or 'E'), right-hand side rhs and range range (NaN for none) imposes on its activity, as MPS defines ranges: [rhs − |range|, rhs] for 'L', [rhs, rhs + |range|] for 'G', and for 'E', [rhs, rhs + range] or [rhs + range, rhs] by the sign of the range.

Multistage problems

SMPSFormat.SMPSTree — Type
SMPSTree

A problem in more than two periods read by read_smps, with a discrete scenario tree:

min  E[ Σ_t c_t(ξ)' x_t ] + constant
s.t. Σ_{τ ≤ t} A_tτ(ξ) x_τ ~ b_t(ξ)   for each period t   (senses, ranges)
     lb ≤ x ≤ ub,  some of them integer,
     x_t depends only on the history of ξ up to period t (nonanticipativity)
  • The core data, in the order of the core file: c, A (rows × columns), senses, rhs, ranges (NaN for none; see row_bounds), lb, ub, integer, constant. colperiod[j] and rowperiod[i] give the period of each column and row, among periods.
  • Random elements: elements lists them as (kind, i, j): (:rhs, i, 0) is the right-hand side of row i; (:A, i, j) the coefficient of column j in row i; (:c, j, 0) the cost of column j; (:lb, j, 0) and (:ub, j, 0) its lower and upper bounds. names gives, for each, the column and row names of the files, or, for a bound, its type (LO or UP) and the column; elementperiod its period: that of its row, or of its column for a cost or a bound.
  • The tree: node n lies in period nodeperiod[n], has the parent parent[n] (0 for the root, node 1) and the probability probability[n], the sum of those of the scenarios through it. values[n] holds the values its random elements of that period take there (element => value); an element it does not list keeps its value in the core file.
  • The scenarios: scenarios[s] is the path of scenario s, its node in each period; scenarionames[s] and scenarioprobability[s] its name and probability, as read (see probability_sums in read_smps).
  • Sense: as for SMPSProblem, a maximization is stored as the minimization of the opposite objective: the costs, random ones included, and the constant are negated.

scenario_data gives the data of one scenario, bundles the scenarios that share a node, and, with JuMP loaded, extensive_form the deterministic equivalent on the tree.

source
SMPSFormat.SMPSStagewise — Type
SMPSStagewise

A problem in more than two periods read by read_smps from INDEP and BLOCKS sections: its random data are revealed period by period, independently from one period to the next (stagewise independence), and the law of each period is an SMPSLaw. Its scenario tree, the product of these laws, is not built: scenario_tree builds it when it is small enough, sample_tree samples one, and rand(rng, s) draws the data of one scenario.

  • The core data and the random elements are those of an SMPSTree: c, A, senses, rhs, ranges, lb, ub, integer, constant, colperiod, rowperiod; elements, names, elementperiod (the period of the data each element sets).
  • The law: laws[t] is the law of the elements revealed in period t, whose values form its ξ in the order of lawelements[t] (indices in elements); laws[1] has none. revealperiod[e] is the period element e is revealed in: the one its INDEP line or its block gives, at most the period of its data (a demand of period 3 may be known in period 2). base holds the values of the elements in the core file.
  • Sense: a maximization is stored as the minimization of the opposite objective, the costs, random ones included, and the constant negated.

SMPSFormat.scenario_tree — Function
scenario_tree(smps::SMPSProblem; limit = 100_000)
scenario_tree(smps::SMPSProblem, ξ, p)
sample_tree([rng,] smps::SMPSProblem, n)

The two-stage problem smps as an SMPSTree in two periods, PERIOD1 and PERIOD2: the root and a node per scenario, the first stage before the second. The scenarios are every point of the support of its law (an error beyond limit), those given (ξ, as enumerate_scenarios or rand give them, with the probabilities p), or n draws of its law, each with probability 1 / n. What applies to trees then applies to it: scenario_data, bundles, extensive_form, write_smps.

source
scenario_tree(s::SMPSStagewise; limit = 100_000)

The scenario tree of s, as an SMPSTree: each node of period t − 1 has a child for each point of the support of the law of period t, with the product of the probabilities; the nodes are numbered depth first, scenario by scenario, as read_smps numbers those of a SCENARIOS section. An error if s has more than limit scenarios (sample a tree instead, sample_tree), or continuous elements. A period without random data adds one child to each node.

source
SMPSFormat.sample_tree — Function
sample_tree([rng,] s::SMPSStagewise, branching; common = false)

A scenario tree sampled from the law of s, as an SMPSTree: each node of period t − 1 has branching[t − 1] children (branching a vector of length length(s.periods) − 1, or an integer, the same in every period), each drawn from the law of period t with probability 1 / branching[t − 1] times its parent's. The draws are independent from node to node (conditional sampling); with common = true, the same draws serve every node of a period. A period without random data adds one child to each node. The nodes are numbered depth first, as by scenario_tree.

The deterministic equivalent

SMPSFormat.extensive_form — Function
extensive_form(smps::SMPSProblem, ξ, p; optimizer = nothing)
extensive_form(tree::SMPSTree; optimizer = nothing)

The deterministic equivalent of smps for the scenarios ξ (vectors of the values of the random elements, as enumerate_scenarios or rand give them) and their probabilities p, as a JuMP model: returns (model, x, y), x the first-stage variables and y[s] the second-stage variables of scenario s. The objective includes the constant of the core file, and is in the sense of the problem read: a maximization read with sense = :max is built as a maximization.

On a tree, the deterministic equivalent in its nodal form: the variables of a period are those of each node of that period, x[n] for node n (its columns in the order of the core file, as findall(==(nodeperiod[n]), colperiod) lists them); returns (model, x). Each row of a node involves the variables of the node and of its ancestors, with the values of the node's random elements; the objective weighs the costs of each node by its probability.

Defined when JuMP is loaded (the package extension SMPSFormatJuMPExt).
