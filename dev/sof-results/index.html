StochOptFormat: validation results

SMPSFormat 0.9.0, SDDP.jl 1.15.0, JuMP 1.32.1, HiGHS.jl 1.27.0 (HiGHS 1.16.0), Julia 1.12.1, x86_64-linux-gnu; run on 2026-11-15, instances up to the size medium, 1800 seconds per solve, run in 8 processes, 52.0 minutes in all.

Each instance is written in StochOptFormat by write_sof, read back by SDDP.read_from_file, and the deterministic equivalent SDDP.deterministic_equivalent builds of it solved with HiGHS: with random variables, unless the instance has random coefficients in its rows, which SDDP.jl does not read (—), and with the data of each node. The files are gzipped.

The instances were split among 8 processes by name (--only), their tables merged. rand0-4000 was then run again alone, the computer otherwise idle: run with the other processes, its solve with random variables had reached the time limit. The interior point method without presolve that instances.toml sets for the rand instances fails on SDDP.jl's deterministic equivalent of rand0-4000 with the data of each node (OTHER_ERROR), and reaches the time limit on that of rand0-6000 with random variables: SDDP.jl's deterministic equivalents are larger than SMPSFormat's, with copies of the state variables and the random variables fixed.

  • pltexpA56: PostResults is 1.7e-6 lower, within the accuracy of the solvers on the pltexp problems, which are ill-conditioned: on the deterministic equivalents of COIN-OR SMI, which reads the same problems from these files (their blocks rewritten as scenarios), HiGHS and Clp differ by 2e-6 to 1e-5 on pltexpB3 to pltexpB5. HiGHS gives -23.2140713288 by the simplex method, with tighter tolerances, without scaling or presolve, and by interior points, with the probabilities normalized too; the other pltexpA instances agree to the digits published.
